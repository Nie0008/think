# think

一个独立的中文思维方法 Skill：根据问题的实际缺口，选择、组合和切换合适的方法，把分析落到目标、候选方案、取舍依据和可检查的下一步。

包含 **26 项思考与验证方法**。用户可以直接描述问题，不必先替 AI 选方法，也不需要逐个执行全部方法。

## 快速使用

获取仓库：

```sh
git clone https://github.com/Nie0008/think.git
```

将整个 `think` 文件夹放入你使用的 Agent 客户端的 Skills 目录。若已有同名 Skill，先备份、比较内容，再决定是否替换。

支持 `$skill-name` 调用方式的客户端中，可以这样提问：

```text
$think 我们正在比较几个产品方案，但目标和评价标准不一致。
请根据材料选择合适的方法，给出可执行的建议和仍需确认的问题。
```

也可以直接说明：

```text
请使用 think。先读取这个文件夹里的 SKILL.md，
再按需要读取 references 中的对应章节，分析下面的问题：……
```

最好附上目标、原始材料、已有方案、硬约束和希望得到的结果。缺少的信息可以保留为未知，不需要为填满方法表格编造数字。

这个 Skill 由当前 Agent 独立使用，没有必需的其他 Skill、调度服务、MCP、脚本或模型配置。Skills 的发现与调用语法以具体客户端为准；不支持自动发现时，可以显式要求读取 `SKILL.md`。

## 按什么选方法

| 需要解决的问题 | 方法与参考 |
| --- | --- |
| 目标不清，或方案空间过窄 | [价值聚焦 VFT、广义形态分析 GMA、C–K](references/goals-and-options.md) |
| 行动冲突、长期张力或改变反复受阻 | [冲突消解图、两极管理、因果分层 CLA、改变免疫地图](references/conflicts-and-change.md) |
| 多属性取舍、信息不足或长期不确定性 | [等价交换、信息价值 VoI、动态适应路径 DAPP](references/decisions-under-uncertainty.md) |
| 多方理解不同，或项目争用资源 | [软系统 SSM、组合决策 PDA、生态循环](references/scenarios.md) |
| 前提、样本或因果判断可疑 | [第一性原理、反向检验、可证伪、选择偏差、基础率、因果与反事实](references/assumptions.md) |
| 旧承诺、可逆性、失败路径或关键参数影响决策 | [旋转门、单向门与双向门、事前验尸、敏感性分析](references/decisions.md) |
| 需要从讨论走向实际核验 | [对抗性分析、独立复算与复现、最小验证试验](references/verification.md) |

例如：

- “先确定我们究竟希望改善什么，再生成现有选项之外的方案。”
- “这些项目有共同前置工作，请检查可行组合，而不是只给单项排名。”
- “哪条未知最可能改变选择？取得它需要什么成本？”

这些是使用请求示例，不是效果验证记录。

## 使用边界

方法用于改善问题表述、生成候选和设计检查，不保证结论正确。原始数据、来源、计算、实际运行和使用者判断仍决定结论是否成立；多个方法得到相同答案也不等于完成验证。

来源中的实验、理论、管理经验与本 Skill 的提示改写分别看待。文献支持某个机制，不表示这些提示已经逐项证明能改善模型或业务效果。探索时可以提出假设，形成建议与行动依据时再核对关键前提。
