# think

一个独立的中文思维方法 Skill。遇到目标不清、方案难选、需求冲突或信息不足时，让 AI 根据实际问题选择方法，给出可检查的分析、候选方案和下一步。

包含 **26 项思考与验证方法**，可以用于产品规划、运营、流程改进、学习和个人项目。你不需要先学完这些方法，也不需要与任何示例中的人物有相同背景。

**上手路径：安装整个文件夹 → 调用 think → 给出本次任务的背景与材料 → 检查建议的依据和执行条件。** 当前 Agent 即可独立使用，没有必需的其他 Skill、调度服务或额外脚本；模型和文件访问能力由你使用的客户端提供。

## 安装与确认

安装的是整个 `think` 文件夹，里面应直接包含 `SKILL.md` 和 `references/`。只复制 README 或只下载 `SKILL.md`，会缺少详细方法说明。

### 选择安装位置

| 客户端 | 个人使用：跨项目可用 | 项目使用：放在项目根目录下 |
| --- | --- | --- |
| Codex 本地 Skills | `~/.agents/skills/think/` | `.agents/skills/think/` |
| Claude Code 本地 Skills | `~/.claude/skills/think/` | `.claude/skills/think/` |
| 其他能读取文件的 Agent | 按客户端的 Skills 设置安装；也可放在普通目录，通过完整路径调用 | 确保该 Agent 有权读取整个文件夹 |

路径及调用规则参考 [Codex 官方文档](https://learn.chatgpt.com/docs/build-skills)与 [Claude Code 官方文档](https://code.claude.com/docs/en/skills)。这里说明本地安装；云端会话需要在它实际可访问的环境中提供文件。

**任选一个位置安装即可。** 已有同名 `think` 时先备份、比较，不要直接覆盖或在多个目录重复安装。

### 方式一：用 Git 安装

下面的命令适用于 macOS、Linux 或 Git Bash，需要先有 Git。

**Codex，个人使用：**

```sh
mkdir -p "$HOME/.agents/skills"
git clone https://github.com/Nie0008/think.git "$HOME/.agents/skills/think"
```

**Claude Code，个人使用：**

```sh
mkdir -p "$HOME/.claude/skills"
git clone https://github.com/Nie0008/think.git "$HOME/.claude/skills/think"
```

若只想在一个项目中使用，在该项目根目录执行对应的一组命令：

```sh
# Codex
mkdir -p .agents/skills
git clone https://github.com/Nie0008/think.git .agents/skills/think
```

```sh
# Claude Code
mkdir -p .claude/skills
git clone https://github.com/Nie0008/think.git .claude/skills/think
```

### 方式二：不用 Git，下载 ZIP

1. 在本仓库点击 **Code → Download ZIP**，解压。
2. 将解压得到的 `think-main` 文件夹改名为 `think`。
3. 把它放到上表所选的位置。Windows 用户也可以用文件管理器完成这些操作，`~` 表示当前用户的主目录。
4. 检查目录层级：应为 `think/SKILL.md`，不要多套一层变成 `think/think-main/SKILL.md`。

### 确认装好，再开始提问

打开客户端的技能列表，确认存在 `think`；若未显示，重新开启会话，仍无变化再重启客户端。也可以直接要求 Agent：

```text
请找到并读取已安装的 think/SKILL.md，告诉我实际读取的路径，
以及其中“信息不足时决定下一步查什么”对应哪一份参考文件。
如果读不到，请说明缺少的路径或文件访问权限，不要假装已加载。
```

这一步确认文件可读；技能列表可见、文件已读取、建议正确是三件需要分别检查的事。

## 怎么调用

### 在客户端中点名调用

| 使用环境 | 调用示例 |
| --- | --- |
| Codex CLI / IDE 扩展 | `$think 帮我比较下面两个方案，并指出会改变选择的未知。` |
| Claude Code | `/think 帮我比较下面两个方案，并指出会改变选择的未知。` |
| 有技能选择器的桌面客户端 | 在列表中选中 `think`，再输入任务；具体提及符号按客户端界面操作 |

`$think` 和 `/think` 是客户端中的技能调用写法，不是终端命令。安装后，在对话输入框里使用。

### 不支持技能列表时，明确要求读取入口

先把示例中的 `实际路径` 替换成你安装的目录，再发送：

```text
请使用 think。先读取“实际路径/think/SKILL.md”，
再根据问题按需读取同目录 references 中的相关章节。

我的问题是：……
目标与限制是：……
我提供的材料是：……
请给出建议、关键依据、仍未知的部分和下一步。
```

如果是只能接收上传文件的聊天工具，提供 `SKILL.md` 与需要的参考文件，或提供客户端能够解压读取的完整文件包；先确认它实际读到了内容。仅发送你的本地路径或仓库链接，不代表对方能访问文件。

### 让它自行选方法，也可以指定方法

通常直接写“使用 think 分析这个问题”即可，让它按缺口选择，必要时组合或切换。材料清楚、能直接计算的小问题，可以直接完成，不要求凑满方法数量。

已经知道卡点时，也可以写：

```text
使用 think 的信息价值分析：我已经有两个候选方案，
请判断哪一条未知最可能改变选择，以及如何低成本核实。
没有可信概率就给条件判断，不编造期望收益。
```

无需要求“把26种方法各跑一遍”或“每种方法派一个 Agent”。本 Skill 的内容是思维方法，不负责配置协作队伍。

## 不同背景的人怎么用

**安装一次，随任务提供你自己的上下文即可；通常不必改 Skill。** 同一套方法能服务不同职业，决定怎样分析的是当前目标、可用证据、资源与决策权限。

| 你提供什么 | 为什么有用 | 写法示例 |
| --- | --- | --- |
| 本次的角色、服务对象与决定范围 | 确定替谁比较、谁受影响、哪些决定你能做 | “我是小组协调者，为5名成员安排工作，只能调整任务顺序，不能增加人手。” |
| 目标与优先级 | 区分真正要达成的结果和眼前手段 | “先保证交付可讨论的样例，再考虑说明是否完整。” |
| 硬约束 | 排除根本不可行的方案 | “本周最多6小时，不能新增付费工具。” |
| 当前状态、原始材料与候选 | 让分析落在可核对的事实上 | “已完成哪些工作、原始表格在哪里、两个方案各包含什么。” |
| 未知与偏好 | 避免 AI 替你补出概率、权重或他人意见 | “没有收益数据；我更重视稳定性，但尚未决定愿意为此多花多久。” |
| 希望得到的产物 | 决定分析到什么深度、何时可以停 | “一页建议、可行组合和下一条值得核实的信息。” |

不必提供姓名、单位、完整履历或私人档案。只给与任务有关的信息；涉及其他人的材料先按自己的披露权限处理。工作资料可以留在私有项目中，任务里指定允许读取的文件，不要把个人背景写回这个公开仓库。

可以从下面的模板开始，不知道的项写“未知”：

```text
请使用 think，根据当前缺口选择方法，不必逐个套用。

本次角色与服务对象：
我要作的决定／解决的问题：
目标与优先级：
硬约束（时间、预算、权限、不能改变的规则）：
当前状态（尤其是已经投入或完成的部分）：
已有方案与原始材料（附正文或可读取的路径）：
已知事实与来源：
假设、未知和我尚未确定的偏好：
希望得到的结果形式：

先给建议，再说明关键依据、成立条件、仍未知的部分与下一步。
若缺少会显著改变结论的材料，请指出；能独立完成的部分先继续。
```

角色或任务发生变化时，更新这段背景。例如同一个人替团队安排资源，与为自己安排学习，目标和约束可能完全不同。旧任务的工时、偏好和规则不能自动沿用；请明确本次材料与旧背景的差异。

若还说不清目标，不必强行填完模板。先提供当前困惑、谁受影响和不能接受的结果，让 think 帮你把要决定的问题说明白。

## 四个可复制的使用示例

下面都是自拟演示输入，可以直接替换成自己的条件。**它们展示怎样提问及检查产物，不是已经取得业务效果的案例。** 以下采用通用“使用 think”写法；也可换成客户端对应的 `$think` 或 `/think`。

### 示例一：产品负责人，不想在两个既定方案里硬选

```text
使用 think。我负责一个小型预约产品，正在决定下月优先做什么。
团队目前只提了“增加报表”和“重做首页”两个方案。

5次客服记录中，3次提到用户看不清预约状态，
2次提到取消入口难找；这是收到的反馈样本，没有全部用户的分母。
我能安排2个开发日，不能重做整个系统。
目标是减少用户找不到状态和取消入口的问题。

请检查现有选项是否覆盖目标，给出其他可行候选和最值得先试的一项。
说明需要怎样核实，不要把5次反馈当成所有用户的比例。
```

可能有帮助的切入：价值聚焦、选择偏差检查、最小验证试验。看结果是否把目标与“增加报表”等手段分开，产生符合2天限制的候选，并留下可检查的试用安排。

### 示例二：小组协调者，几项工作共用一份准备材料

```text
使用 think。小组本周只能投入6小时，先希望拿出可讨论的样例，
同时尽量有操作说明。各项工作都是完整任务，每项至多一次。

A：整理通用输入，2小时。
B：制作方案样例，3小时，必须先完成A。
C：编写操作说明，2小时，也必须先完成A。
D：准备现状访谈问题，1小时，可以独立做，不包含实际访谈。
A由B、C共用，只计一次。各项收益未知。

请检查可行组合，建议先做什么，给出顺序、余量及最值得补的一条信息。
若中途换方案，要计入已经花掉的时间。
```

可能有帮助的切入：组合决策、定性信息价值。一个可以手工核对的点是：A+B+C需要7小时；A+B+D需要6小时；A+B需要5小时。不能通过“共享A”把完整样例与完整说明塞进6小时，也不能把D的准备工作写成已经获得反馈。具体选哪一组仍取决于讨论所需的最小成品与缓冲需要。

### 示例三：运营与设计，双方坚持的行动相互冲突

```text
使用 think。我协调一个活动页面，运营要求“周五上线所有内容”，
设计要求“全部页面审完才能上线”。

双方明确认可的需求：运营要赶上已确定的活动日期；
设计要避免价格、规则和品牌信息出错。
已知：主要活动页已审完，两个辅助页未审完，周五是硬截止。
尚未知：辅助页能否晚些开放，以及现有审核制度是否允许分批发布。
我只能提出方案，不能擅自批准例外。

请把需求与坚持的做法分开，检查冲突背后的假设，
提出可讨论的替代安排，并写清要找谁确认什么。
不要把你提出的方案写成双方已经同意。
```

可能有帮助的切入：冲突消解图、信息价值。检查是否出现了满足双方需求的替代安排，以及安排成立所需的制度、范围和授权条件；如果硬约束仍冲突，应明确需要取舍。

### 示例四：学习者，判断计划是否有效

```text
使用 think。我在练习英文技术文档阅读，每周能用3小时，
希望更准确地找到操作步骤，而不只是觉得自己“读得更多”。

目前两种候选：每天泛读短文；每周精读一份文档并完成对应练习。
我的真实基线还没测，也没有两种方式的效果数据。
请设计一个小范围验证：先测什么、如何安排可比较的任务、
记录哪些结果，以及什么情况下继续、调整或暂时无法判断。
不要仅凭一次做得快就宣布某种方式有效。
```

可能有帮助的切入：可证伪检验、最小验证试验、因果与反事实。看结果是否区分阅读量与完成任务的准确性，考虑任务难度和练习效应，并保留小样本无法确定的部分。

## 26种方法分别适合什么场景

不必记住名称，先找与你当前卡点接近的一行。点击方法名可查看具体输入、用法、误用边界与来源。

### 目标与新方案

| 方法 | 适用场景 | 应得到的产物 |
| --- | --- | --- |
| 1. [价值聚焦 VFT](references/goals-and-options.md#价值聚焦思考-vft) | 只在“买A还是B、做哪个功能”中挑选，真正目标不清 | 根本目标与实现手段的关系、原选项之外的新候选 |
| 2. [广义形态分析 GMA](references/goals-and-options.md#广义形态分析-gma) | 目标较清楚，但方案总是熟悉组合 | 维度与状态表、不相容理由、值得细化的完整候选 |
| 3. [概念—知识扩展 C–K](references/goals-and-options.md#概念知识双空间扩展-ck) | 想创造的产品或服务，现有知识还无法判定是否成立 | 概念分支、已有知识及每个分支要补的知识任务 |

### 冲突、张力与改变

| 方法 | 适用场景 | 应得到的产物 |
| --- | --- | --- |
| 4. [冲突消解图／蒸发云](references/conflicts-and-change.md#冲突消解图蒸发云) | 双方用冲突的行动满足各自合理需求 | 共同目标、需求、行动及连接假设，可兼顾需求的新做法 |
| 5. [两极管理](references/conflicts-and-change.md#两极管理) | 稳定与探索等两端确实需要长期共存，却总是顾此失彼 | 两端好处、过度侧重的代价、行动与预警信号 |

| 7. [改变免疫地图](references/conflicts-and-change.md#改变免疫地图) | 本人想改变却反复受阻，明显的资源与技能障碍已检查 | 本人认可的目标、妨碍行为、竞争承诺和可检验假设；不替他人诊断动机 |

## 怎么检查回答是否有用

看它是否帮助你作出决定或执行下一步，而不只是在正文中出现了方法名：

- 推荐是否满足真实约束，数字是否能从原始材料复算，已投入资源是否正确计入。
- 是否新增了有价值的候选、解释或检查，而不是把原话换成一张表。
- 事实、假设和你的偏好是否分开；缺少分母、材料或他人意见时是否保留未知。
- 是否说清建议何时成立、什么信息会改变它，以及下一步由谁检查什么。
- 计划、演示、实际执行与效果是否分清；不能把虚构数据、多种方法一致或模型自评当成验证。

若回答只有方法名，可以追问：“请把它落到我给的材料上，给出具体候选或计算、成立条件和下一步；不需要展示冗长思考过程。”

## 更新与常见问题

**怎样更新？** 用 Git 安装的版本，先进入实际安装目录，查看本地改动，再更新：

```sh
# 先切换到你实际安装的 think 目录，再执行
git status --short
git pull --ff-only
```

有个人改动时先备份、审阅差异，不要强制覆盖。ZIP 安装则重新下载，备份旧目录后替换。更新后若客户端仍读取旧内容，重新开启会话并核对实际文件路径。

**文件读不到或调用不生效？** 检查目录层级、权限与重名 Skill；明确提供 `think/SKILL.md` 的实际路径，要求回报读取到的路径。云端工具不能因为你本机安装过，就自动读取本机目录。

**需要提供长期个人资料吗？** 不需要。短任务只提供相关上下文；复杂任务可引用自己私有的项目说明。背景缺失时先给条件判断或追问，不让 AI 猜你的职业、资源和偏好。

**换模型或换职业要重写吗？** 通常不需要修改方法文件。把同一目录提供给能读取这些文件的 Agent，并更新本次背景即可；文件可读不代表各模型效果相同。

**需要其他 Skill 或多 Agent 吗？** 不需要。think 由当前 Agent 独立使用。联网查证、运行计算或领域工具取决于任务与客户端能力；它们提供证据与执行能力，方法说明本身不能替代。
